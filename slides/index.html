Los geht’s: dein erster Befehl

Melde dich an deiner VM an, starte PowerShell 7 und tippe:

PS> $PSVersionTable.PSVersion
PS> Get-Help Get-Service -Examples

Version 7.x? Dann kann es losgehen. Steht dort 5.1, hast du Windows PowerShell gestartet.

Alle gemeinsam einloggen, jede Person bestätigt die Version. Danach Wechsel zu Kapitel 1 der Kursseite (Tag 1).

Woher kommt PowerShell?

  • 2002: Jeffrey Snover schreibt bei Microsoft das „Monad Manifesto“
  • Die Idee: Administration mit Objekten statt Text, aufgebaut auf .NET
  • 2006: Aus „Monad“ wird Windows PowerShell 1.0
  • 2016: Open Source, plattformübergreifend

Der Kerngedanke

Die Pipeline transportiert Objekte, nicht Text. Deshalb muss man nichts zerlegen (parsen).

Hintergrund: Windows hatte lange keine gute Shell, Administration war GUI-lastig. Unix-Shells reichen Text weiter, Monad reicht .NET-Objekte weiter. Der Namenswechsel zu PowerShell wurde im April 2006 angekündigt, 1.0 erschien im November 2006. Quellen: Wikipedia „PowerShell“, Microsoft Learn.

Wie hat sie sich entwickelt?

Daten: 1.0 im Nov. 2006; 2.0 im Okt. 2009 (Windows 7/Server 2008 R2: Remoting, ISE); 5.1 im Aug. 2016 (Windows 10 Anniversary, Server 2016) ist die letzte Windows-PowerShell; Aug. 2016 Open-Source-Ankündigung (MIT-Lizenz); 6.0 im Jan. 2018; 7.0 im März 2020; 7.6 LTS im März 2026 auf .NET 10. LTS-Versionen erscheinen etwa alle zwei Jahre.

Beide laufen nebeneinander. Die Grundlagen sind gleich, Unterschiede markieren wir im Kurs.

Wichtig: Windows PowerShell 5.1 verschwindet nicht, es ist Bestandteil von Windows. Wer „PowerShell“ sagt, meint im Alltag oft beides. Deshalb immer die Version prüfen.

Was ist neu in PowerShell 7?

Ternärer Operator

$s = $dienst.Status -eq 'Running' ? 'läuft' : 'steht'

Null-Coalescing

$name = $eingabe ?? 'Standard'

Pipeline-Verkettung

Test-Path C:\Kurs && Write-Output 'da'

Parallel arbeiten

1..5 | ForEach-Object -Parallel { $_ * 2 }

Dazu: bessere Fehlermeldungen, modernes .NET, schneller, plattformübergreifend, Remoting auch über SSH.

Diese Syntax gibt es in 5.1 nicht. Wer Skripte für beide Versionen schreibt, muss darauf achten. Details: Kursseite, Kap. „PowerShell vs. CMD“ (Tag 1) und „Verzweigungen“/„Schleifen“ (Tag 2).

Welche Version nehme ich wann?

PowerShell 7 für

  • neue Skripte und Automatisierung
  • Cloud, Linux, Container
  • alles, was wir im Kurs tun

Windows PowerShell 5.1 für

  • Altbestand und alte Skripte
  • Module, die nur 5.1 kennen
  • Server ohne PowerShell 7

Welche habe ich gerade?

PS> $PSVersionTable.PSEdition # Core = 7, Desktop = 5.1
PowerShell 7 lädt viele Windows-Module über eine Kompatibilitätsschicht; erzwingen mit: Import-Module X -UseWindowsPowerShell. Im Lab sind beide installiert.

Die ISE: ein Auslaufmodell

  • Grafischer Editor für Windows PowerShell, seit 2009
  • Nur für 5.1, nicht für PowerShell 6 und 7
  • Keine neuen Features, nur noch Sicherheits- und kritische Fixes
  • Nur Windows

Du begegnest ihr

  • auf älteren Servern
  • in alten Anleitungen und Skripten
  • bei Kollegen mit Gewohnheit

Microsoft empfiehlt als Ersatz Visual Studio Code mit der PowerShell-Erweiterung.

Quelle: Microsoft Learn „Introducing the Windows PowerShell ISE“. Die ISE ist weiterhin Teil von Windows und wird für Sicherheitsfixes gewartet, bekommt aber keine neuen Funktionen und läuft nicht mit PowerShell 7.
